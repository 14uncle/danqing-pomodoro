# Memory: 商店更新检查 API 的坑

> 2026-09-05 update-check 侧载实测揪出; 与 [[store-iap-windows-crate-pitfalls]] 同边界:
> 仅 MSIX 环境可达, 单测/clippy 全盖不住

## 坑

- **`StorePackageUpdate.Package` 是「被更新的当前包」, 不暴露新版本号**:
  `GetAppAndOptionalStorePackageUpdatesAsync` 返回的更新项里 `Package.Id.Version`
  恒等于**当前安装版本** —— 新版本号不可得, 商店轨「有更新」只有有无、没有版本。
  提示文案只能写「有新版本」, 别设计显示新版本号的 UI。
- **商店服务栈对刚侧载的包有注册延迟**: 装完立刻查可能返回空列表;
  过几分钟 (商店库页面已认出更新) 再查才有。侧载验证更新链路前,
  先确认商店库页面能看到更新, 否则会把平台延迟误判成代码 bug。
- **诊断手法**: `Size()` 计数 + 一行 info 日志直接打印待装更新数,
  一刀分开「商店真空」与「自家代码吞掉」两类故障; 别凭空猜。

**Why:** 商店 API 的语义陷阱在文档字里行间, 编译期与单测都验不出来;
首次实跑前就把日志桩埋好, 能省一轮重打包。

**How to apply:** 商店轨任何「查更新/查目录」新链路, 先假设拿不到对面版本号;
实测先看日志计数, 再谈 UI。
