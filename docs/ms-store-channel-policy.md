## 一句话规则

「**开源 + 免费 + freemium**」：源码在 GitHub 开源，可自由编译得到完整版；开箱即用的二进制——无论 GitHub Release 还是微软商店——**都只送 2 个基础场景**（篝火、海）+ 番茄钟计时 + 环境音；其余 7 场景 + 数据统计 + 年度报告 + CSV/JSON 导出 = **商店买断 ¥18（首发 ¥7.9）或自行编译**。

## 两渠道边界（同一条规则, 不打架）

| 功能 | GitHub Release (免费二进制) | 微软商店 (freemium) |
|------|--------------------------|---------------------|
| 开箱场景 | 2（篝火、海） | 2（免费层） |
| 其余 7 场景 | 自行编译 `cargo build --release --features full` | 买断解锁 |
| 统计 / 年度报告 / 导出 | 自行编译 | 买断解锁 |
| 获得完整版途径 | 编译（源码开源） | 商店买断 或 编译 |
| 付费点 | 无 | 买断解锁 |

**关键语义**：「免费」指**开源 + 免费二进制**；完整版不是直接白送物，而是「**编译（开源）或买断（商店）**」二选一。这一条把「GitHub 白送完整版 → 商店 ¥18 卖不动」这个自我拆台点关掉了。

## 为什么这样设计

- 商店付的不是「功能」，是**开箱即用 + 自动更新 + 微软账号生态**（付费锚定信任/在场/分发，见 [[product-strategy-two-gates]]）。
- 开源承诺仍在——源码完整公开，会编译的人免费拿全部；只给伸手党免费二进制（2 场景），不让「免费」成为商店 ¥18 的解药。
- 两渠道同一条规则，任何读者一句话能说清「免费到哪、收费到哪」，不再有「GitHub 有完整版干嘛买商店」的矛盾。
