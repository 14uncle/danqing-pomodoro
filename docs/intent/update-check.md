# 意图：双轨应用内更新感知 (update-check)

- **日期**: 2026-09-05
- **状态**: 意图已确认（interview-me 访谈锁定），待进 spec 阶段
- **下一工序**: `/agent-skills:spec`，按 spec → plan → build → review → code-simplify 推进，不直接编码

## 背景 (Why now)

2026-09-05 上架商店新版本后发现：应用内零更新感知——用户连自己在哪个版本都看不到，
GitHub 便携包用户装完即孤岛，商店用户只能撞运气打开微软商店看更新按钮。

## 确认的意图

- **Outcome**: 两条分发轨各自获得应用内更新感知。
  - 商店轨：启动静默查 `StoreContext`，有新版时给出提示，点了在应用内直接拉商店更新。
  - GitHub 轨：启动静默查 GitHub Releases API，有新版时给出提示，点了跳发布页手动下载。
- **User**: 商店付费用户 + GitHub 便携包免费用户。
- **Success**:
  1. 用户不离开应用就知道「我在哪个版本、有没有新版」；
  2. 商店付费用户永远不会被指向 GitHub 免费版；
  3. 用户不点设置面板也能发现有新版本（角标）。
- **Constraint**:
  1. 轨道用 `store` feature **编译时隔离**，二进制物理上不可能指错轨道
     （商店版只查商店、绝口不提 GitHub；便携包只查 GitHub、不知道商店存在）；
  2. 不打断专注——启动静默检查，无弹窗，结果落在设置页一行「版本 vX.Y.Z / 有新版本 →」；
  3. 检查结果缓存 24h，不每次启动都打 API（GitHub 免认证限流 60 次/小时）；
  4. 断网/检查失败静默跳过，当没这回事；
  5. GitHub 轨引入 `ureq` + rustls，这是全应用第一个也是唯一一个网络依赖；
  6. 有新版本时主界面设置按钮出现角标（主题色点），版本追平后角标消失。
- **Out of scope**: GitHub 轨自动下载替换 exe（文件锁/重启逻辑，复杂度不值）；
  两轨互相感知；设置页大改版；不碰 `focus-history.json` 数据格式。

## 访谈关键决策记录

- **双轨冲突问题**（用户提出）：商店版若查 GitHub Releases，会把已付费用户导向免费便携版，
  解锁状态（商店 IAP）在便携包中不存在，等于付费降级 + 双安装并存。
  解法：复用现有 `store` feature 编译时分界，反向（GitHub 用户看到商店）无害，不管。
- **不对称深度（B 方案）**：商店轨做应用内拉更新是因为 `windows` crate 的 `Services_Store`
  已是 IAP 查许可证的现成依赖，边际成本近零；GitHub 轨自动更新才是真复杂度，砍掉。
- **角标修订**（用户在 yes 时追加）：没有角标，设置页里的更新行曝光率为零，功能白做。
